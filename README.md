# 测试开发知识汇总

用来系统复习测试开发岗的计算机基础 + 工程能力，目标是**能在工作里直接用、在面试里讲清楚**。
每篇的原则：不写概念定义，写"这件事在测开工作中出现在哪、怎么验证、哪里会踩坑"。

> 📖 **不想逐篇点开 md？** 直接双击根目录的 **`测试开发知识库.html`**：
> 左侧分组目录、顶部全文搜索、右侧本篇大纲、代码块带高亮和一键复制，单文件离线可用。
>
> 🌐 **想分享给别人看？** 见仓库里的 `DEPLOY.md`——推到 GitHub 后自动部署成在线站点，
> 以后只要 push Markdown 就会自动更新，不用买服务器。

## 命名与拆分规则

- 命名格式：`测试开发-<主题>篇.md`，一个主题一个文件。
- 判断是否拆篇：**如果两块的"复习动作"不一样，就拆开**。网络篇要抓包发畸形报文，OS 篇要调并行数造互锁，MySQL 篇要写 SQL 对账，Linux 篇要 grep 日志 —— 混在一起读会互相打断。
- 清单已全部覆盖（10 批 32 篇）。后续如需扩展，按同样规则新增：一个主题一个文件，命名 `测试开发-<主题>篇.md`。

## 怎么用这套材料

**第一遍（建框架，11~12 天）**：只看每篇开头的"自查分级表"和每节小标题，知道有哪些东西、哪些是熟练档。不要逐字读。

**第二遍（补短板，按档位）**：从"会用但说不清"那一档开始读，每个知识点读完立刻回答一句"这东西在我现在的项目里用在哪"。答不上来的，就是真的缺。

**第三遍（动手，最关键）**：每篇末尾都有「动手清单」，32 篇一共 142 条，全部做完比读三遍有效得多。这些都设计成**在你自己的系统上能立刻执行**的动作，不是练习题。

**面试前（巩固表达）**：只看每篇的「自查清单逐条作答」小节和代码注释。答案都按"先结论、再场景、再坑"组织，可以直接照着说。

## 三个贯穿全篇的判断标准

这三个标准比背知识点重要，因为工作和面试真正考察的是它们：

1. **能不能说清"这个知识点在故障现场的哪个位置"**。比如 TIME_WAIT，能说出"在压测机上说明我连接没复用，在服务端上说明是服务端主动关闭"，就比背 2MSL 强。
2. **能不能说出"测试这一步要验什么、怎么造出这个场景"**。缓存雪崩谁都会说，能说出"批量写 key 看 TTL 是否集中，或直接重启 Redis 观察降级"，才是测开。
3. **能不能分清"该提 bug"和"该确认设计"**。很多"不符合规范"的现象其实是设计取舍（比如业务失败也返回 200），先确认约定再定性，是专业度的分水岭。
